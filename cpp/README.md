# CuteTTS.AXERA C++ runtime (AX650)

纯 C++（AX_ENGINE + STL）实现完整 TTS 链路，不依赖 Python/numpy：

```
参考 wav ─ vae_enc ─┐
          spk_body ─┴─> prompt embeds (embedding 表 + locenc_step)
                       lm_prefill ─> hidden / KV cache
   loop: hidden ─ dit_step ×4 ─> latent
         latent ─ locenc_step ─> embed ─ lm_decode ─> hidden / new KV
   latents ─ vae_dec_l{64,128,256} ─> 24 kHz wav
```

主机侧只做：WAV 读写、重采样（polyphase FIR）、log-mel（512 点 FFT）、
embedding 查表、线性投影、mask/RoPE/KV 拼接、4 步 Euler、高斯噪声。

## 编译

```bash
TOOLCHAIN_ROOT=/path/to/gcc-arm-9.2-2019.12-x86_64-aarch64-none-linux-gnu \
BSP_MSP_DIR=/path/to/ax650n_bsp_sdk/msp/out \
bash cpp/build_ax650.sh
```

缺少工具链/BSP 时会调用 `cpp/download_toolchains.sh` 自动下载。

## 运行

```bash
# 非流式（整句生成后一次性解码，RTF 最低）
./bin/cutetts_ax650 --model-dir models --assets models/assets \
  --text "The voice generated by this model sounds amazing!" \
  --reference samples/reference.wav --output out.wav

# 真流式（边生成边解码写盘，首包 ≈1.3 s）
./bin/cutetts_ax650 ... --output out.wav --stream
```

流式实现：AR 循环连续产生 latent，`vae_dec_stream` 逐 patch 解码（2 latent = **160 ms 一包**）。
该图把解码器 31 个因果卷积的左侧上下文变成 18 个显式状态张量（0.46 MB），
每步输入 `latent[1,64,2]` + 状态，输出 `wav[1,1,3840]` + 新状态，主机侧零拷贝。

默认是**精确滑动窗**：每 16 个 latent（1.28 s）用 `vae_dec_l80` 的 80 长度窗口解码
（前 64 个 latent 作因果上下文），解码器感受野 60 latent，因此与离线**逐样本一致**。
首包只等 4 个 latent：TTFA（首个音频）≈0.48~0.54 s（参考特征缓存命中）/ 1.18 s（首次），
其中 TTFT（首个 latent）≈0.17~0.22 s / 0.87 s。

参考特征缓存：同一参考音频第二次起走 `cache/ref/`（可用 `--ref-cache <dir>` 指定），
跳过 `vae_enc` + 音色编码，TTFA 降低约 0.4 s（首次 0.89 s → 命中 0.47~0.52 s）。
首次的参考特征落盘推迟到首包发出之后（NFS 写一次约 0.2 s，不占 TTFT/TTFA）。`--stateful` 保留旧的逐 patch 状态解码
（160 ms 一包，速度最快但会有轻微底噪，需额外编译 `vae_dec_stream`）。

参数：`--cfg`（默认 2.0）、`--seed`（42）、`--max-new`（最多 patch 数，1 patch ≈ 160 ms）、
`--debug-ids`（只打印 tokenizer 结果，用于和 Python 对拍）。

## 与 Python SDK 的一致性

- tokenizer：`assets/tokenizer.bin` 由 `python/export_assets.py` 从 `tokenizer.model`
  导出（SentencePiece **BPE** 模型：按 merge 优先级合并，不是 unigram Viterbi），
  与 HF tokenizer 的 added-token 切分逐 id 一致
- log-mel：`torch.stft(center=True)` 等价实现，cosine 1.0
- 其余数值全部在 NPU 上，输入输出与 Python SDK 相同
